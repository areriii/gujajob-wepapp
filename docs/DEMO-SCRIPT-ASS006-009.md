## ฉากที่ 1 — ASS-006 แจ้งขอจำหน่าย (3-4 นาที)

### 1.1 ให้ดูรายการก่อน

ชี้ให้เห็นว่ามี 8 ใบ และ**สถานะไม่เหมือนกัน** — รอการอนุมัติ / อนุมัติแล้ว / ไม่อนุมัติ
พูดว่าระบบคุมสถานะของแต่ละใบแยกกัน และกรองตามสถานะได้

### 1.2 สร้างใบใหม่สด — โชว์กฎธุรกิจตรงนี้

กด **เพิ่ม** → หน้าแจ้งขอจำหน่าย

| ช่อง | กรอกอะไร |
|---|---|
| เลขที่ใบขอจำหน่ายครุภัณฑ์ | **ไม่ต้องกรอก** ระบบรันให้เป็น `SL2569009` — ชี้ให้อาจารย์เห็นว่ารันเลขอัตโนมัติตามปี พ.ศ. |
| วันที่แจ้งขอจำหน่าย * | วันนี้ |
| หน่วยงานผู้แจ้งขออนุมัติ | ระบบใส่ "ฝ่ายพัสดุ" ให้เองจากบัญชีที่ login |
| เหตุผลในการจำหน่าย * | **เลือก "หมดอายุการใช้งาน" ก่อน** |
| หมายเหตุ | "ครบอายุการใช้งานตามเกณฑ์" |

**จุดที่ควรหยุดอธิบาย** — ค้นหาจาก = `รหัสครุภัณฑ์`, คำค้นหา = `DEMO` → กด **ค้นหา**

ระบบจะขึ้นมา**รายการเดียว** คือ DEMO-ASSET-013 พูดว่า

> "เหตุผล 'หมดอายุการใช้งาน' ระบบบังคับว่าครุภัณฑ์ต้องตัดค่าเสื่อมราคาจนเหลือมูลค่า 1 บาทแล้วเท่านั้น ทั้งฐานข้อมูลมีตัวเดียว ระบบจึงกรองให้เหลือตัวนี้"

จากนั้น **เปลี่ยนเหตุผลเป็น "ชำรุดจนซ่อมแซมไม่ได้"** → ค้นหา `AI-TEST-02` อีกครั้ง → จะเจอหลายรายการ

> "พอเปลี่ยนเหตุผลเป็นชำรุด เงื่อนไขมูลค่าคงเหลือไม่ถูกบังคับ ระบบจึงให้เลือกได้ 41 รายการ"

### 1.3 บันทึก

กด **เพิ่ม** 2 รายการ → ตารางล่างจะมีคอลัมน์ มูลค่าครุภัณฑ์ / ราคาจำหน่ายขั้นต่ำ / ราคาที่ขายได้จริง (สองช่องหลังยังว่าง — บอกว่าจะถูกเติมในขั้นอนุมัติกับขั้นบันทึกผล) → **บันทึก** → **ยืนยัน**

กลับมาที่รายการ จะเห็น `SL2569009` สถานะ **รอการอนุมัติ**

## ฉากที่ 2 — ASS-007 อนุมัติแจ้งจำหน่าย (3 นาที)

### 2.1 อนุมัติ SL2569001 สด

เปิด **SL2569001** → **พิจารณา**

| ช่อง | กรอกอะไร |
|---|---|
| วันที่พิจารณา * | วันนี้ |
| ราคาขายขั้นต่ำ * (รายการที่ 1) | `3000` |
| ราคาขายขั้นต่ำ * (รายการที่ 2) | `1500` |

ชี้ให้เห็นว่าตารางมี **มูลค่าครุภัณฑ์** กับ **มูลค่าคงเหลือ** ให้ผู้อนุมัติใช้ตัดสินใจตั้งราคา

กด **อนุมัติ** → **ยืนยัน** → สถานะเปลี่ยนเป็น **อนุมัติแล้ว**

### 2.2 โชว์สองเคสพิเศษ (เปิดดูเฉย ๆ ไม่ต้องกด)

- **SL2569002 (สูญหาย)** — เปิดหน้าพิจารณาแล้วจะเห็นว่า**ไม่มีช่องราคาให้กรอก** พูดว่า "ของสูญหายไม่มีการขาย ระบบจึงข้ามขั้นตอนตั้งราคาให้เลย"
- **SL2569008 (ไม่อนุมัติ)** — เปิดดูจะเห็นหมายเหตุ *"ตรวจสอบแล้วครุภัณฑ์ยังอยู่ในสภาพใช้งานได้ ให้ซ่อมบำรุงแทนการจำหน่าย"* พูดว่าระบบบังคับกรอกเหตุผลเมื่อไม่อนุมัติ

## ฉากที่ 3 — ASS-008 บันทึกผลการจำหน่าย (3 นาที)

เปิดรายการ → ชี้ว่า**มีแต่ใบที่อนุมัติแล้วเท่านั้นที่ขึ้นหน้านี้** (ใบที่ยังรออนุมัติกับใบที่ถูกตีกลับจะไม่มา)
และ **SL2569001 ที่เพิ่งอนุมัติเมื่อกี้จะโผล่มาในรายการนี้** — ชี้ให้เห็น เป็นจุดที่เชื่อมสองหน้าเข้าหากันชัดที่สุด

### 3.1 บันทึกผลสด

เปิด **SL2569001** → **บันทึกผล**

| ช่อง | กรอกอะไร |
|---|---|
| ผู้รับซื้อ * | `ร้านรับซื้อของเก่า ทรัพย์เจริญพาณิชย์` |
| ราคาที่ขายได้จริง * (รายการที่ 1) | `4200` |
| ราคาที่ขายได้จริง * (รายการที่ 2) | `1800` |

กด **บันทึก** → **ยืนยันการบันทึก** → สถานะเปลี่ยนเป็น **จำหน่ายแล้ว**

พูดปิดฉากว่า

> "ตอนบันทึกผล ระบบจะไปปรับสถานะในทะเบียนครุภัณฑ์ให้เป็น 'จำหน่ายแล้ว' ด้วย ทะเบียนกับใบจำหน่ายจึงไม่ขัดกัน"

### 3.2 โชว์ใบที่จบแล้ว

- **SL2569006** — จบแบบมีผู้ซื้อ มีราคาขายจริงครบทุกรายการ
- **SL2569007** — เหตุผลสูญหาย ไม่มีผู้ซื้อ ราคาขายจริง 0 แต่ระบบนับว่า "จบแล้ว" เหมือนกัน

## ประเด็นที่ควรชูให้อาจารย์เห็น

อาจารย์มักถามว่า "ระบบคุมอะไรให้" — เตรียมตอบสี่ข้อนี้

1. **กันครุภัณฑ์ซ้ำสองใบ** — ครุภัณฑ์ที่อยู่ในใบที่รออนุมัติหรืออนุมัติแล้ว จะไม่ขึ้นให้เลือกในใบอื่น (แต่ถ้าใบถูกตีกลับ ระบบปล่อยให้เลือกใหม่ได้)
2. **เงื่อนไขตามเหตุผล** — "หมดอายุการใช้งาน" บังคับมูลค่าคงเหลือ 1 บาท / "สูญหาย" ข้ามขั้นตอนราคาทั้งหมด
3. **ลำดับขั้นบังคับ** — ยังไม่อนุมัติ จะบันทึกผลไม่ได้ (หน้า ASS-008 ไม่แสดงใบที่ยังไม่อนุมัติเลย)
4. **ข้อมูลไหลข้ามหน้า** — อนุมัติที่ ASS-007 แล้วใบไปโผล่ที่ ASS-008 / บันทึกผลที่ ASS-008 แล้วสถานะในทะเบียนครุภัณฑ์เปลี่ยนตาม

## ข้อควรระวัง (อ่านก่อนขึ้นเวที)

- **ช่องค้นหาในหน้า ASS-009 ต้องคลิกเลือกจากรายการ** พิมพ์เองแล้วกดพรีวิวเลยไม่ได้ ระบบจะเตือน "กรุณาเลือกจากรายการที่ระบบแสดง" เพราะค่าจริงเก็บตอนคลิกเลือก
- **"กองคลัง" มีสองรายการในฐานข้อมูล** (ทั้งคู่มีหน่วยงานย่อยชื่อ "ฝ่ายพัสดุ" ด้วย) ถ้าเลือกผิดตัวรายงานจะว่าง → **เลือกตัวแรก** ถ้าพรีวิวออกมาว่าง กดย้อนกลับแล้วเลือกอีกตัว
- **รายงานทะเบียนครุภัณฑ์ต้องเลือกทั้งหน่วยงานและหน่วยงานย่อย** กรอกแต่ปีงบประมาณแล้วกดพรีวิวจะได้ error "กรุณาเลือกหน่วยงานและหน่วยงานย่อย" — อย่าเดโมแบบกรอกแค่ปี
- **เลี่ยงประเภท "เครื่องคอมพิวเตอร์ ชนิดกระเป๋าหิ้ว (Notebook)" ใน ASS-009** เพราะช่องรหัสครุภัณฑ์แสดงรหัส*ประเภท* ไม่ใช่รหัสครุภัณฑ์ จะเห็นตัวเลือกหน้าตาเหมือนกัน 3 บรรทัด แยกไม่ออก → ใช้เครื่องถ่ายเอกสารตามสคริปต์
- **อย่ากดปุ่มลบ** ระหว่างเดโม ข้อมูลชุดนี้เตรียมมาให้พอดี ๆ
- รายงานจะมีหมายเหตุติดมาว่า *"[ALLOCATION DEMO DATA] ข้อมูลทดสอบระบบจัดสรร/รับครุภัณฑ์ ห้ามใช้เป็นข้อมูลจริง"* เป็นข้อความที่ติดมากับข้อมูลทดสอบ ถ้าไม่อยากให้โชว์ต้องแก้ข้อมูลก่อน
- **รายงานทะเบียนครุภัณฑ์แสดงเฉพาะครุภัณฑ์สถานะ "ปกติ" เท่านั้น** จึงออกมาแค่ 1 รายการ ถ้าอาจารย์ถามว่าทำไมน้อย ตอบได้ว่ารายงานนี้กรองเฉพาะของที่อยู่ในทะเบียนใช้งานปกติในปีงบนั้น
